# AURA.MONEY - Developer Platform & Workflow

This document defines the permanent local development platform and workflow for AURA.MONEY. It guarantees a reproducible, deterministic environment for all engineers and AI agents.

## 01 Development Workflow
The standard path from clone to productive contribution:
1. **Clone Repository:** `git clone <repo-url> && cd auramoney`
2. **Install Dependencies:** `npm install`
3. **Configure Environment:** Copy `.env.example` to `.env.local` and populate keys.
4. **Start Services:** `npm run supabase:start` (Boots local DB, Auth, Edge Functions).
5. **Apply Migrations & Seed:** `npm run db:reset` (Applies all migrations from zero and injects the Dev Seed).
6. **Generate Types:** `npm run db:types` (Generates TS definitions based on the DB schema).
7. **Run Application:** `npm run dev` (Starts Next.js server).
8. **Run Tests:** `npm run test`
9. **Reset Environment:** `npm run db:reset` (To wipe slate clean during active dev).
10. **Update Dependencies:** Managed carefully via PRs; never arbitrary updates on `main`.

## 02 Standard Scripts
The `package.json` defines all necessary scripts. No manual Docker or DB commands are needed.
- `dev`: Start the local Next.js dev server.
- `build`: Build the Next.js production bundle.
- `lint`: Run ESLint.
- `typecheck`: Run TypeScript compilation check (`tsc --noEmit`).
- `test`: Run all test suites (unit + integration).
- `test:unit` / `test:integration` / `test:e2e`: Granular test execution.
- `supabase:start` / `stop` / `status`: Manage local Supabase Docker infrastructure.
- `db:migrate`: Push new schema changes without resetting data.
- `db:reset`: Wipe local DB, apply all migrations from scratch, run local seeds.
- `db:seed`: Explicitly inject seed data.
- `db:types`: Introspect local DB and generate `src/shared/types/database.types.ts`.
- `db:verify`: Check if all local migrations are successfully applied.
- `clean`: Purge `.next`, `node_modules` for a fresh installation.
- `format`: Auto-format code via Prettier.
- `check`: **Complete Repository Health Check.** Runs validation, lint, types, tests, and build.

## 03 Environment Validation
Running `npm run check:env` invokes `scripts/verify-env.js`.
This script automatically verifies:
- Node.js version (LTS v20+).
- Package manager availability (`npm`).
- Supabase CLI availability.
- Missing configuration (`.env.local`).
It fails fast with clear error messages before booting the app, preventing obscure runtime crashes.

## 04 Repository Health Check
`npm run check` is the comprehensive gatekeeper. It executes:
1. Environment validation (`check:env`)
2. Linting (`lint`)
3. TypeScript compiler (`typecheck`)
4. Test suites (`test`)
5. Application build (`build`)
*(Architecture boundaries are checked during linting via ESLint rules).*

## 05 Git Hooks
We rely on Husky and `lint-staged`.
- **pre-commit:** 
  - Validates formatting (Prettier).
  - Runs linting and architecture boundary validation (ESLint).
  - Validates conventional commits.
- **pre-push:**
  - Runs the full `npm run check` (Typecheck, tests, and build). Prevents broken code from reaching the remote repo.

## 07 Generated Artifacts
Automatically generated files must NEVER be manually edited:
- **Database Types:** `src/shared/types/database.types.ts`. Regenerated by `npm run db:types` after any schema change.
- **Build Output:** `.next/` directory. Handled by the framework.
- **Coverage Reports:** `coverage/` directory. Dropped on test runs.

## 08 Troubleshooting Guide
- **Supabase Not Running / Port Conflicts:** Ensure Docker is running. If ports clash (e.g., 5432), run `npm run supabase:stop`, kill offending processes, and `npm run supabase:start`.
- **Migration Failure:** If local state is corrupted, run `npm run db:reset` to nuke and recreate the local environment.
- **Type Generation Errors:** Usually indicates a broken local migration. Check `supabase:status`, fix the bad `.sql` file, run `db:reset`, then `db:types`.
- **Broken Seeds:** If seed data violates constraints, the `db:reset` command will output the specific SQL error. Correct `supabase/seed.sql` and run `db:reset` again.

## 09 Onboarding Checklist
New contributors must complete this on day one:
- [ ] Clone the repository.
- [ ] Verify Node v20 is installed.
- [ ] Run `npm install`.
- [ ] Run `npm run check:env`.
- [ ] Run `npm run supabase:start`.
- [ ] Run `npm run db:reset` (generates tables + seeds).
- [ ] Run `npm run db:types`.
- [ ] Run `npm run dev` and navigate to `http://localhost:3000`.
- [ ] Run `npm run check` successfully.
